# v177 リリースノート

## 変更点

### 最終話の判定に先読みの結果を使い、二重取得をやめた

- 先読み（`prefetchNextChapter()`）は `catch(()=>null)` で失敗理由を捨てていた。このため「次話→」を押すと `page` が偽値のまま再取得のループに入り、**存在しないページをプロキシ経由でもう一度まるごと取得**していた。最終話のメッセージが出るまで待たされる原因はこれで、小説サイトへの無駄なアクセスも1回発生していた。
- 先読みの失敗理由を `_nextErrCache` に保持し、再取得しても結果が変わらない確定的なエラーであれば、取得せずに即座に結果を出すようにした。一時的なプロキシ失敗は従来どおり再取得する。
- 読んでいる間に次話が公開される場合があるため、先読みの判定は `PREFETCH_ERR_TTL_MS`（30分）だけ有効とし、それより古い場合は取得し直す。キャッシュは章の移動で必ず破棄されるため、影響は同じ章に留まっている間に限られる。
- `localStorage` の構造は変更していない。話数が連番でないカクヨムにも同じ仕組みが効く。

### 最終話の判定条件を自前プロキシの404に限定した

- `HTTP <番号>` を投げているのは `tryProxy()` の1か所だけで、必ず `fetchHtml()` に集約される。このため「`HTTP 404` を含むか」という文字列照合は、**通信障害で全プロキシが失敗したときのメッセージにも一致**していた。どれか1つのプロキシが自分自身について404を返しただけで最終話と判定されうる状態だった。
- `fetchHtml()` は `PROXIES` で `own: true` を付けた自前プロキシから404を受けた場合にのみ、エラーに `own404` を立てる。判定は `isFinalErr()` に集約し、このフラグと「最終話の可能性」メッセージのみを根拠とする。
- 公開プロキシの404はプロキシ自身についての応答であり、ページの有無を示さないため対象外とした。

### 取得エラーの詳細表示を設定で切り替えられるようにした

- 設定タブのデバッグモード欄にトグルを追加した（`yogatari_err_detail`、既定OFF）。ONにすると、取得失敗時にプロキシごとの理由（`📋` 以降）を表示する。
- 音声の計測ログとは独立したトグルにしてある。デバッグモードをONにすると音声要素に計測ラッパーが入るため、理由を見るためだけにONにするのは副作用が大きいため。
- フィルターは各 `throw` 側ではなく `showFetch()` に置き、`📋` 以降を落とす方式とした。目次取得の失敗・話ページ読込の失敗・章送り中の失敗のすべてが同じスイッチで覆われる。
- あわせて失敗理由の打ち切りを解消した。従来は `fetchHtml()` が6件までに制限し、章送り側がさらに160文字で切っていたため、`PROXIES` が増えた状態では理由の一部が見えなかった。`errors` は応答順に積まれるため、どれが欠けたかも特定できなかった。

### PROXIES を7件に整理した

- **`api.cors.lol` を自前2件の直後（index 2）に追加。** なろう・カクヨムの本文ページとも取得できることを実機で確認した。カクヨム本文がDeno Deploy単独依存になる状態を解消した。末尾ではなくこの位置に置いたのは、以降の公開プロキシが到達不能なものばかりで、末尾では起動まで待たされるため。
- **`yacdn.org` と `thingproxy.freeboard.io` を削除。** いずれもDNSが解決せず（ドメイン消滅）、回復の見込みがない。
- `cors.eu.org`（運営者のCloudflare Workers無料枠の上限に達し `Error 1027`）と `api.codetabs.com`（サーバー停止中で `522`）は残置した。DNS・CDNの層までは生きており復旧しうるため。

### CLAUDE.md の修正・追記

- **`fetchHtml()` が `sessionStorage` にキャッシュする、という記述を訂正した。** 実際に `yogatari_pc_*` を読み書きするのは `resumeFrom()`（履歴からの再開）だけで、通常の読込・章送り・先読みは毎回取得している。キー一覧も併せて修正した。
- 最終話の判定が自前プロキシの404に依存することを記録した。プロキシ側がページの不在以外の理由で404を返すと誤判定につながるため、改修時の制約として明記した。
- カクヨムの本文ページに関する403の記述に、2026-09-21の再検証結果を追記した（後述）。
- 「削除済みで再追加してはならないプロキシ」の一覧を追加した。コードから消すと削除の理由も消えるため、Web上の一覧に載り続けているプロキシを再び候補として持ち込む余地が残るため。記録するのはドメイン消滅・APIキー必須化など「構造的に戻らない事実」のみとし、速度や混雑といった変動する情報は書かない方針を明記した。

## 実測で確認した事項（2026-09-21）

すべて実機（iOS Safari / iPadOS Safari）で確認した。

### カクヨムの本文ページをCloudflare Workers経由で取得できた

- 同じ本文ページに対し、自前のCloudflare Workersプロキシが `status: 200` / `attempts: 1`（再試行なしの一発成功）を返した。Deno Deploy も同じ `bytes: 57528` を返しており、2系統が同一コードであることの裏付けにもなった。
- 同日、`api.allorigins.win` と `api.cors.lol` も同じ本文ページを取得できた。
- v176で記録した「本文ページはCloudflare Workers経由では403」という実測は、**経路そのものに対する恒久的な拒否ではなく、カクヨム側のIP単位の制限が続いていた状態だった可能性がある**。ただし200の観測は1回のみで、403が再発しない保証はない。CLAUDE.mdには両方の記述を残した。

### 公開プロキシの死活

| プロキシ | 結果 |
|---|---|
| `api.cors.lol` | 作品ページ・本文ページとも取得成功。アプリのオリジンからも `HTTP 502` のステータスを読めており、CORSは通っている |
| `api.allorigins.win` | 本文ページの取得成功 |
| `cors.eu.org` | `Error 1027`（運営者のCloudflare Workers無料枠が上限）。時刻を変えて2回とも同じ |
| `api.codetabs.com` | `522`（Cloudflareは通るが先方サーバーが応答しない）。URL形式の末尾スラッシュ有無による差は、サーバーに到達しないため判定できなかった |
| `yacdn.org` | 「サーバが見つかりません」。DNSが解決しない |
| `thingproxy.freeboard.io` | 「サーバが見つかりません」。DNSが解決しない |

### 自前プロキシのdebugエンドポイント

- `?debug=1` は `url` パラメータと併用する必要がある（`?debug=1&url=<encoded>`）。単体で叩くと `Missing url param` を返す。アプリは常に `?url=` を付けるため動作には影響しない。

## 決定事項

- **`cors.eu.org` の順位は上げない。** 外部評価では最有力とされていたが、実機では常時枠切れであり、われわれの用途では使用できない。
- **一時的な失敗を理由にプロキシを削除しない。** 削除はドメイン消滅・APIキー必須化など構造的に回復しない事実に限る。
- **最終話の判定は自前プロキシの404のみを根拠とする。** 自前プロキシ2件とも404以外を返し公開プロキシだけが404を受け取った場合は最終話と判定されず通常のエラー表示になるが、誤判定を避けることを優先した。
- `sessionStorage` のページキャッシュを `fetchHtml()` 側へ移す案は、挙動の変更を伴うため見送った。
