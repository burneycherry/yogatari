# v174 リリースノート

## 変更点

### エブリスタ（estar.jp）に対応
- 本文セレクタは `.mainBody .content`。従来指定していた `#novel-content` / `.novel-content` は現在のサイトに存在せず、汎用フォールバックの「最も文字数の多いdiv」が偶然本文を拾っていただけだった。
- 章扉ページには `.content` が無いため、見出しを含む `.mainBody .body` をフォールバックとして併記する。
- **`rule.body` のカンマ区切りを優先順位リストとして順に試すよう変更した。** `querySelector()` にカンマ区切りを渡すと文書順で最初の要素が返るため、親要素である `.body` が常に選ばれ、話タイトル（`h1.subject`）が本文の先頭に重複していた。他サイトへの影響は無い（なろう・青空文庫は単一セレクタ、カクヨムは `.p-novel__body` が引き続き優先される）。あわせてテキストが空の要素は採用しないようにした。
- 本文の最小文字数を `SITE_RULES` の `minText` でサイトごとに指定できるようにし、エブリスタは 2 とした。章扉の見出しは「序章」「第1章　命」のように短く、既定の30文字では正常なページをエラーとして弾いていた。本文セレクタが具体的なため、短い一致でも本文と判断して差し支えない。
- 作品タイトルはビューアページの `<title>`「`【本文】<作品名>｜<N>ページ - 小説投稿エブリスタ`」から抽出する。従来は `extractPage()` の作品タイトル抽出がなろう専用で `novelTitle` が null となり、`currentNovelTitle` が話タイトルへフォールバックして履歴に話タイトルが作品名として保存されていた。
- `chapNumFromUrl()` が `?page=` から話数を読むようにした。従来は末尾が数字でないため常に1話目として扱われていた。
- `inferTocUrl()` が `/viewer?page=N` を落として目次URLを導出するようにし、新着チェックに分岐を追加。目次ページの「全NNエピソード」から総話数を取得してNEWバッジを表示する。
- 話URLから読み込む運用で、**目次ページからの話選択には非対応**（目次解析はなろう専用のため）。

### 青空文庫（www.aozora.gr.jp）に対応
- 本文セレクタは `.main_text`。
- 青空文庫のXHTMLはShift_JISで配信されるが、`Response.text()` は仕様上つねにUTF-8としてデコードするため、全文が `U+FFFD` に潰れて文字化けしていた。`needsSjisDecode()` が対象ホストを判定し、`arrayBuffer()` を `TextDecoder('shift_jis')` でデコードする。
- JSONで包むプロキシ（allorigins の `/get`）はUTF-8デコード済みの文字列しか返さず復元不能なため、Shift_JISのページでは取得対象から外す。
- ルビは既存の `ruby` フィルターが `rt` のテキストを採用するため、そのまま機能する。
- 1作品1ファイルのため章間ナビゲーションは無い。**本文ファイル（`/files/〜.html`）のURLを指定する**。図書カードのページには本文が無い。

### 全段落が省略された場合の安全弁
- `splitText()` に追加。フィルター後に1段落も残らなかった場合に限り、フィルター前の行を返す。
- エブリスタの章扉ページは見出し1行のみで構成され、既定ONの `chaphead`（章・話タイトル行、`/^第[一二三四五六七八九十百千\d]+章/`）に一致して全段落が消え、セグメント0件となり再生できなかった。
- **影響は全行がフィルターに一致するページのみで、通常の話の省略挙動は変わらない。** なろうの章扉ページも同様に読み上げられるようになる。

### CORSプロキシ（Cloudflare Workers）の更新
- Worker側はこのリポジトリの管理外だが、v174の動作前提として以下を反映済み。
  - ホワイトリストに `estar.jp` / `www.aozora.gr.jp` / `www.alphapolis.co.jp`（およびwww有無の別名）を追加。
  - `Response.text()` によるデコードをやめ、**ボディをバイトのまま転送**して元の `Content-Type` を引き継ぐ。Workers の `TextDecoder` はUTF-8（とWindows-1252）しか保証されないため、Shift_JISの変換はクライアント側で行う。
  - 調査用に `&raw=1` で `text/plain` として返す分岐を追加（元のcharsetを維持）。

### ヘルプ（使い方）の全面見直し
- 見出しを「夜語り — 使い方」から「使い方」へ変更。
- iOS向けの注意書き（「最初に ▶ を1回タップ」）を削除。読むタブの同趣旨のヒント（`iosHint`）も削除した。`unlockAudio()` の解除用 `play()` は直後の `stopGoogleAudioFull()` で必ず中断されるため `.then` 内の非表示処理が走らず、常時表示のまま残っていた。未使用となったCSSと非表示処理も削除。
- セクション順を 基本の使い方 → Google TTS → バックグラウンド再生 → 再生コントロール → 睡眠タイマー → しおり・履歴 → 新着話の自動検出 → 対応サイト → 非対応サイト に変更。
- 端末内蔵音声になる条件を「APIキー未設定のとき」から「再生音声の選択が端末内蔵音声のとき」へ修正（v173でエンジン選択がAPIキーの有無と分離済みのため）。バックグラウンド再生の条件も同様に修正し、重複していた2項目を1項目へ統合。
- タップシークの説明を実装に合わせた。5秒単位で動くのはGoogle音声のときのみで、端末内蔵音声では1段落単位の移動になること、画面中央と下部はタップに反応しないことを明記。
- 旧称「Kyoko」の表記を「端末内蔵音声」へ統一（ヘルプ・読み間違い辞書モーダル・使用量警告バー）。
- 見出しを「未対応サイト」から「非対応サイト」へ変更し、一覧を実態に合わせて更新。

## 決定事項

- **アルファポリスは非対応として確定した。** プロキシ経由でのHTML取得自体は成功するが、本文コンテナ `<div id="novelBody">` は空で、本文はページ表示後にJavaScriptが別途取得して埋める構造のため静的HTMLからは得られない。1話がさらに18ページ程度に分割される。また `content-viewer.js` がコピー・選択・右クリックの禁止、フォーカス喪失時の本文非表示、スクリーンショット阻止といったコンテンツ保護を実装しており、これを迂回する実装は行わない方針とした。調査の過程で追加したセレクタ `#novelBoby` は現在のサイトに存在しないことが判明したため削除した。
- **ハーメルンは非対応として確定した。** 公開プロキシ経由でページ自体には到達するが、返るのはCloudflareのチャレンジページで `tryProxy()` のブロック検出が働く。自前Workerのホワイトリストにも追加していない。
- エブリスタの章扉ページは飛ばさず、章題を読み上げてから次へ進む方式を採用した。飛ばす方式は判定を誤ると短い話を落とす危険があるため。
- エブリスタの `toNovelId()` は変更していない。履歴の重複が発生していないことを実機で確認済みであり、作品IDの体系変更は `localStorage` のデータ構造変更にあたるため。

## 未実装・対応予定なし

- Service Worker / オフライン対応: 引き続き対応予定なし
- SSMLポーズ最適化: 削除済み、復活予定なし
- アルファポリス・ハーメルン: 上記の理由により対応予定なし
- エブリスタの目次ページからの話選択: 目次解析はなろう専用のため未対応
