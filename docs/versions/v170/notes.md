# v170 リリースノート

## 変更点

### 履歴の🔗（目次ページへのリンク）修正
- 長編作品（1000話超等）で🔗をタップすると、実際に読んでいる話とは異なるページ（本来より手前のページ）に着地する不具合を修正。
- 調査の結果、真因は「目次ページを直接読み込んで章を選択した場合、`bk.tocUrl` に入力URL（`?p=13` 等のページ番号付き）がそのまま保存されていた」こと。🔗リンクのページ算出時にこのURLへさらに`?p=`を付け足す形になり、`...?p=13/?p=16` のような壊れたURLになって常に元のページに戻ってしまっていた。
- 章URL（`bk.chapterUrl`）から素のTOC URL（クエリなし）を再導出する経路を優先し、`bk.tocUrl` を使う場合もクエリ文字列を必ず除去するよう修正。`bkSetToc()` 側でも保存時にクエリを除去し、今後の汚染を防止。
- （調査過程で一時的に、複数ページを取得して厳密一致を探す非同期処理を追加したが、根本原因の特定後は不要と判断し撤去。単純な同期計算に戻している。）

### 目次解析の誤カウント修正
- `parseSyosetuToc()` のフォールバック処理（主要セレクタ不一致時）が「数字で終わるURL」だけで章リンクを判定していたため、書籍化告知に含まれるAmazon・楽天・ヨドバシカメラ等の商品リンク（ISBNなど数字で終わるURL）まで話として誤カウントしていた。
- フォールバックを同一ホスト・同一ncodeの `/ncode/数字/` 形式のURLのみに限定し、無関係なリンクを除外。

### 履歴のNEW話数バッジを仕様変更
- 従来は「前回チェック時からの増加分」を `hasNew`/`newDiff` フラグとして保存し、1話でも読み進めると（未読が残っていても）バッジが消えていた。
- 「最新の総話数（`bk.totalChap`）− 現在の既読話数（`bk.chapterNum`）」を描画のたびに算出する方式に変更。未読が残っている限りバッジが表示され続ける。不要になった `hasNew`/`newDiff` の読み書きは削除（localStorageの既存データに残っていても無害・未使用）。

### NEWバッジが更新されない不具合の修正
- 最新総話数のチェック（`checkNewChapter`）はこれまでアプリ起動3秒後の一括チェック（`startupNewCheck`）でのみ実行されていたが、履歴からすぐ読書を再開すると `_resumeActive` フラグでこのチェックループが `break` し、それ以降の作品が一切チェックされない抜け穴があった。
- 履歴から読書再開した際（`resumeFrom()`）にも `checkNewChapter()` をバックグラウンドで実行するよう追加。
- 上記の追加により、起動時の一括チェックと再開時のチェックが同一作品に対して同時実行される場合があり、競合で片方がAPI失敗→HTML目次1ページ目のみのフォールバック（最大100話分）に落ちて、実際より大幅に少ない話数で上書きされる問題が発生（例: 本来+200話前後のところ+40話に）。同一作品への `checkNewChapter()` の多重実行を防止する仕組み（`_checkInFlight`）を追加し、新たに算出した総話数が既知の値より小さい場合は上書きしない安全策も追加。
- さらに、目次1ページ目のみのカウントでは100話超の作品を過小カウントする問題自体を解消するため、ページネーションの最終ページ番号を検出してそのページも取得し、正確な総話数を算出するよう修正。
- 最終的に、起動時の一括チェックが読書再開中に全体を`break`していた挙動を`continue`（その1件だけスキップして他は続行）に変更し、履歴タブを開くたびの重複チェック処理は撤去（起動時チェック1本に統一）。

### 広告ラベル行のスキップフィルター追加
- なろうチアーズプログラム参加作品等で本文中に挿入される「PR」「広告」「AD」等の単独行（広告の目印）が読み上げに混ざる問題を修正。
- 既存のスキップフィルター機構（`CONFIGURABLE_FILTERS`）に新フィルター（`adlabel`）を追加。行全体が完全にそのラベルだけの場合のみ反応し、文中に「PR」等の文字が含まれる通常の文章までは消さない。設定タブからON/OFF切り替え可能（デフォルトON）。
