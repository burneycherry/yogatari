# v176 リリースノート

## 変更点

### カクヨムの話タイトルが本文中のあいさつ文に置き換わる問題を修正
- `splitText()` の `_pendingEpTitle` は、本文中の `^第[一二三…]+話` に一致する行を話タイトルとして採用していた。位置を問わず採用していたため、本文の途中・末尾にある「第一話読んでくださりありがとうございます！」のようなあいさつ文が、サイト側が持つ正しい話タイトル（「第1話　社畜おっさん、悪役貴族に転生する。」）を上書きしていた。
- 見出しは本文の先頭にしか現れないため、**話タイトルとして採用する対象を先頭3行までに限定**した。章見出し行（第X章）からの抽出・省略挙動は変更していない。

### カクヨムの次話・前話URLが404になる問題を修正
- 話IDはページ内のデータから取るのに、**作品IDだけはアドレス欄のURLから取って文字列連結**していた。保存済み・貼り付けURLの作品IDがカクヨム側のものと異なると、話IDが正しくても必ず「お探しのページは見つかりませんでした」になる。
- `kakuyomuWorkIdOf()` を追加し、`canonical` / `og:url` / 現在の話へのリンクから**ページ自身が名乗る作品ID**を取得する（取れない場合のみ従来どおりURLから取る）。
- `kakuyomuEpisodeUrl()` を追加し、対象の話IDを含むリンクがページにあれば**その href をそのまま使う**。無い場合のみ上記の作品IDで組み立て、6桁未満のIDは採用しない。
- `rel=next/prev`・`__NEXT_DATA__`・リンク文言（「次のエピソード」等）による検出をすべてこの作品IDで照合するよう統一した。リンク文言による検出はカクヨムでも有効にしたが、同一作品の話URLかつ明示的な次話・前話の文言のときのみ採用する（目次一覧の「→」等を誤って拾わないため）。

### カクヨムの目次が先頭7話までしか出ない問題を修正
- 作品ページはリンクとしては**開いている章の先頭7話分しか描画しない**（残りは「つづきを表示」で遅延読み込み）。実機のHTMLを調査したところ、**`__NEXT_DATA__` の Apollo ストアには全話分**（実測138話）の `Episode:<id>`（`title` / `publishedAt` を持つ）が入っていた。
- `kakuyomuApolloState()` / `kakuyomuTocFromState()` を追加し、目次をストアから構築する。追加のリクエストは発生しない。
- **並び順はストアのキー順ではなく参照リストから取る。** キー順の `TableOfContentsChapter` は章の表示順と一致しない。章の一覧 → 各章が参照する話、の順にたどる。
- `publishedAt` が未来の話は目次に載せない（公開予定のため読めない）。章に属さない話・章立てのない作品はストアの順序で末尾に追加する。ストアから取得できない場合は従来のリンク走査へフォールバックする。
- 副次的に、目次の1件目に「1話目から読む」ボタンが混ざる表示上の問題も解消した。

### カクヨムのNEWバッジが誤った話数を出す問題を修正
- 目次の件数が7だったため `7 − 1 = +6話` と表示されていた（実際は全138話）。上記の目次修正で件数が正確になった。
- あわせて `kakuyomuTotalFromToc()` を追加し、章ごとの「30話」ラベルの合計、または「全138話」形式のラベルからも総話数を取得する。ラベルはタグとクラスでグループ化し最大のグループを採る（作品情報等に単独で出る話数ラベルを二重計上しないため）。
- `bkSetToc()` が既知の総話数を小さい値で上書きしないようにした。目次を開き直すと 138 → 7 に戻る経路があったため。

### カクヨムの連続読み込みで403になる問題への対策
- カクヨムは短時間に多数のアクセスを受けたIPを弾く。作品ページは通るのに**本文ページだけ403（nginx）**になる状態が続く。実機で確認した事実は次のとおり。
  - 自前のCloudflare Workersプロキシからは、ブラウザ相当のヘッダー・作品ページで取得したCookieの付与・間隔を空けた再取得のいずれも無効。
  - なろうは同じWorkerから正常に取得できる。カクヨムの本文ページに限った拒否である。
- **Deno Deploy に同等のプロキシを用意し、`PROXIES` の2番目に追加した。** この経路では本文ページを取得できる。
- アプリ側の取得の出し方を見直した。
  - プロキシを2件同時ではなく**1件ずつ500ms間隔**で起動する。各プロキシはそれぞれ小説サイト本体を取得するため、同時起動はサイトから見たアクセス数をそのまま倍にしていた。
  - ホストごとに記憶した成功プロキシがある場合、**他のプロキシの開始を1.5秒遅らせる**。記憶済みが成功すれば他は発火しないため、1ページあたりのアクセスが1回で済む。
  - `HOST_MIN_INTERVAL_MS` を追加し、**カクヨムへの取得間隔に2秒の下限**を設けた。呼び出しごとに次の枠を予約する方式のため、先読みとユーザー操作が同時でも間隔が詰まらない。
  - **次話の先読みをカクヨムのみ12秒後**に変更した（従来0.5秒、他サイトは3秒のまま）。本文取得の直後に先読みが続くのが、弾かれるアクセスパターンそのものだった。
  - 取得失敗（プロキシ全滅）時に**4秒後、1回だけ自動で再取得**する。本文が取れない・最終話等のエラーは従来どおり即座に表示する。失敗メッセージにプロキシごとの理由を併記するようにした。

### プロキシの整理
- **2系統のプロキシは同一コードになった。** エントリポイントのみ両方（`Deno.serve()` と `export default { fetch }`）を用意しており、1つのファイルをそのまま両方にデプロイできる。
- **プロキシはアプリのオリジンからのリクエストのみ受け付ける**（`ALLOWED_ORIGINS`）。`?debug=1` / `?probe=1` はページ本文を返さないため対象外とし、ブラウザから状態を確認できるようにしてある。
- Workerのホワイトリストに `api.syosetu.com` を追加した（なろうの新着チェックAPIが公開プロキシ経由になっていた）。
- APIキー必須化により恒久的に401を返す `corsproxy.io` を `PROXIES` から削除した。

## 決定事項

- **カクヨムの目次は追加リクエストなしでストアから構築する。** 「つづきを表示」が叩くAPIを呼ぶ案もあったが、作品ページのHTMLに全話分が含まれているため不要と判断した。
- **次話・前話のURLはページ自身のリンクを最優先で使う。** 文字列連結は、ページにリンクが無い場合のフォールバックに限定する。
- **カクヨムの本文取得はDeno Deploy経由に依存する。** Cloudflare Workers側の対策（ヘッダー・Cookie・再取得）は実機で無効と確認済みのため、これ以上は追わない。
- **プロキシのコードはリポジトリ管理外のまま**とし、仕様をCLAUDE.mdに文章として残す。完全単一ファイル原則の例外規定は設けない。
- 取得失敗時の最終話判定を「メッセージにHTTP 404が含まれるか」で行う案は撤回した。死んでいるプロキシが自分の都合で404を返すだけで最終話と誤判定され、自動再試行も止まるため。
