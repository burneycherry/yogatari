## 2. 実装アプローチと変更内容

### v144〜v150の破損と再建（最重要教訓）

```
問題: 別セッションでコードがコピペ経由で渡り、以下の変換が発生
  --  → –  (エンダッシュ、iOSスマート句読点)
  _var → *var (Markdown/Claude.aiのitalic解釈で_text_→*text*と誤変換)

影響: nextCount--、_newChapCache、_gVoice、_ov 等の識別子・演算子が破損
     → SyntaxErrorで全JavaScriptが停止 → ボタン操作不可・音声はKyoko固定

対応: v143（ダウンロード運用で無傷）にリベースし、
     v150で意図されていた新機能（カスタムワードフィルター）のみを
     安全な実装方法（IIFE・既存関数への追記）で再実装 → v151
```

### 演算子安全化（v153）

```javascript
// 危険（iOSコピペでエンダッシュ化するリスク）
nextCount--;
removed++;

// 安全（v153以降）
nextCount -= 1;
removed += 1;

// for文の制御部は対象外（この位置のiOS変換は未確認・構文上も安全）
for (let i = 0; i < len; i++) { ... }
```

### NEWバッジ機能の3段階デバッグ（v156→v160→v161）

```
第1段階(v141): items.length（TOCページの表示数、最大100件）では
              1000話超作品の正確な総数が取れない
              → 生HTMLから「全N部分」等のテキストパターンで補完
              → しかしプロキシがこのテキストを含まないHTMLを返すことがあり不安定

第2段階(v156): なろう公式APIに切り替え
              https://api.syosetu.com/novelapi/api/?ncode=X&of=ga&out=json
              XHRコールバック方式で実装
              → 判明した問題A: XHR非同期処理とawaitが噛み合わず、
                startupNewCheckのawaitが意味をなさない
              → 判明した問題B: of=gaのレスポンスが約55文字しかなく、
                tryProxy内の「200文字未満は短すぎ」チェックで弾かれる
                （後のv161で発覚）

第3段階(v160): checkNewChapterを await fetchHtml(apiUrl) 方式に全面書き直し
              → 既存のプロキシ経由フェッチ基盤（tryProxy等）を再利用
              → CORSも回避、async/awaitの整合性も確保

第4段階(v161): &of=ga パラメータを削除し、全フィールド取得（~700文字）に変更
              → 200文字チェックを安定して通過するようになり、
                1000話超作品でも正確な総話数取得・NEW判定が機能するようになった
```

### 目次ページへの直接リンク機能（v158→v159）

```
v158: 履歴アイテムのサムネイル部分を縦分割
     [📖 作品アイコン]
     [🔗 目次リンク]  ← 新規、target="_blank"で外部ブラウザ表示

v159: なろうは1ページ100話区切りのため、しおりの話数から
     正しいページ番号を計算して?p=Nを付加
     pageNum = Math.ceil(chapterNum / 100)
     例: 第110話 → ?p=2 / 第1028話 → ?p=11
     カクヨムはページネーションがないため変更なし
```

### サブタイトル誤認識の原因と修正（v162）

```
前提: なろうページのHTML構造は通常
     行1: 章タイトル（例:「不穏な春を乗り切ろう」）
     行2: 話タイトル（例:「第923話　シャーモン♪　シャーモン♪」）
     行3〜: 本文

目次から読込む場合:
     novel_subtitle取得成功 → currentChapterTitle = "第923話　シャーモン♪…"
     → displayPage内の /^第\d+話?$/ 判定に不一致 → segsスキャンをスキップ → 正常表示

履歴から読込む場合（バグ発生パターン）:
     プロキシがnovel_subtitleを含まないHTML断片を返すことがある
     → currentChapterTitle はURLから生成した "第1030話"（話数のみ）
     → /^第\d+話?$/ に一致 → segsスキャンを実行
     → segs[0]「不穏な春を乗り切ろう」: スキップ（章除去パターン不一致）
     → segs[1]「第923話　シャーモン♪…」: スキップ（既存条件に不一致）
     → segs[2]「ログハウスに戻った私は…『収納』へ…」:
        『』(U+300E/300F)が特殊文字リストに含まれるため誤って採用 ← バグ

修正: 特殊文字チェックの直前に句読点チェックを追加
     if (/[。、，,.]/.test(_s)) continue;
     → 本文は必ず読点・句点を含むためスキップされる
     → 最終的に _pendingEpTitle（splitText内で検出した「第923話…」）が
       currentChapterTitleを正しく上書きする
```

## 5. 重要な決定事項

### 絶対厳守の制約（v140〜v162で判明・強化されたもの）

| 制約 | 理由 |
|---|---|
| **コードのコピペ厳禁**（ファイルはダウンロード→GitHubアップロードのみ） | Claude.aiのチャット経由コピペで`--`→エンダッシュ、`_var`→`*var`に変換されSafariで全停止する実績あり（v144〜150） |
| `--`/`++`演算子は使用せず`-= 1`/`+= 1`を使う | iOSのスマート句読点変換対策（v153で全箇所置換済み） |
| 新規グローバル関数を追加しない（v127セーフティルール） | 既存関数内のIIFEに封じ込める。v121〜v126でグローバル追加によるSafari全壊の実績あり |
| コメント削除は`// [FIX v...]`等の完全一致パターンのみに限定 | 汎用的な`//`除去はURLの`https://`を巻き込み破壊するリスクがある（v157で発見） |
| プロキシ経由のAPI呼び出しはレスポンス最小長（200文字）に注意 | なろうAPIの`of=ga`のような短いレスポンスは`tryProxy`の防御ロジックで弾かれる（v161） |
| なろうAPIはXHRではなく`fetchHtml()`（プロキシ経由）で呼ぶ | CORS回避とasync/awaitの整合性を両立するため（v160） |

### アーキテクチャ・設計判断

- **リベース優先の方針**：バージョンが深刻に壊れた場合、その場でパッチを当てるのではなく、最後に無傷だったバージョンに戻して機能差分だけをクリーンに再実装する（v144〜150破損 → v143リベースでv151作成）
- **段階的デバッグ**：複雑な不具合（NEWバッジ問題等）は一度に全て直そうとせず、1つずつ原因を特定し、ユーザー確認を挟みながらバージョンを重ねる
- **目次リンク機能**：履歴アイテムから外部ブラウザで目次ページを開けるようにし、なろうの100話区切りページネーションを考慮した正確なページ番号（`?p=N`）を自動計算する
- **サブタイトル決定の優先順位**：`novel_subtitle`（DOM）→ h1 → titleタグ → 生HTML正規表現 → segsスキャン（本文からの推測、句読点を含む行は除外）→ `_pendingEpTitle`（splitText内で検出した話タイトル）による最終上書き、という多段フォールバック構造
