# v171 リリースノート

## 変更点

### 前話/次話ボタンの自動再生停止
- 前話/次話ボタン（ハードウェアの前トラック/次トラックボタン含む）を押した際、章の読み込み後に自動で読み上げが開始されてしまい、「再生ボタンを押したら再生」というルールに反していた不具合を修正。
- `goPrev()`/`goNext()`に`autoPlay`引数を追加。ボタン・メディアセッションからの呼び出しは`autoPlay=false`を渡し、章表示後は待機中のまま止まるようにした。章末カウントダウンによる自動進行（既存の章キュー再生機能）のみ、従来通り自動で再生継続する。

### バックグラウンド音声セッション断絶時の自動リロード復帰
- iOS Safariで他アプリ・通話等の音声割り込みが発生すると、フォアグラウンドの再生自体は復帰できてもバックグラウンド再生の権限だけは戻らず、ページの再読み込みでしか正常化しない症状に対応。
- `AudioContext.state`が`'interrupted'`になったこと、またはGoogle TTSの`el.play()`が3回連続失敗したことを断絶の合図として検知（`markBgSessionBroken()`）。検知時は静かな無限リトライをやめて再生停止・しおり保存を行う。
- この状態で次に再生ボタンを押すと、通常の再生開始ではなくしおりを保存してページをリロードし、リロード後は本文位置を自動復元した上でそのまま読み上げを再開する（直前の▶タップをユーザーの再生意思の継続とみなし、リロード後の自動再生を許容。CLAUDE.mdの自動再生禁止ルールの例外ではなく、直前操作の継続として扱う）。

### タブ切り替え時のスクロール位置ずれを修正
- 読む/履歴/設定の3タブは共通の`.scroll-area`内でdisplay切り替えをしているだけで、スクロール位置がタブ間で共有されていた。読む中の自動スクロール分だけ履歴・設定タブが下にずれて表示される不具合があった。
- `switchTab()`にタブごとのスクロール位置記憶・復元処理を追加。各タブは離れる直前の自分の位置に復元される。

### 前話ボタンをページ内の前話リンクから読み込めるよう修正
- 次話ボタンはページ内の「次へ」リンク・URL連番等からセッション履歴に関係なく次話URLを解決していたが、前話はセッション内で実際に前話から遷移してきた記録が無いと常に無効化されており、URL直接入力・履歴再開・前話移動直後などで使えなかった。
- `extractPage()`に次話と対称の前話URL抽出処理を追加（サイトルールのprevセレクタ・PREV_TEXTSでのリンクテキスト一致・`link[rel="prev"]`・なろうのURL連番デクリメント・カクヨムの`__NEXT_DATA__`の`previousEpisode`）。なろうの連番デクリメントは1話目（N=1）では前話URLを生成しないようガードしており、1話目で前話ボタンが無効のままになる挙動は維持。

### 前話ボタンで別の小説の章へ誤って飛ぶ問題を修正
- 上記の対応直後に発覚した不具合。`displayPage()`のprevUrlフォールバックに`currentChapterUrl`（直前に表示していた章）を含めていたため、新しい小説の1話目を読み込んだ際、ページ自体には前話リンクが存在しないにもかかわらず、履歴上の別の小説の章がprevUrlとして使われてしまっていた。
- `currentChapterUrl`は小説をまたぐ判定をしていないため、このフォールバックを削除。`prevUrlHint`（明示的な遷移元）→ページから抽出した前話リンクの2段階のみに整理した。

### 次話取得でHTTP 404の場合も最終話メッセージを表示するよう修正
- 次話取得のエラー分類が、なろう固有の文言（「作品が見つかりません」）でしか最終話を判定しておらず、存在しないエピソードへのアクセスを示すHTTP 404が一律「取得失敗」（ネットワークエラー）扱いになっていた。
- カクヨムで最新話に到達した際、「ページ取得に失敗しました。次話で再試行できます」というリトライしても無意味な誤解を招く表示になっていたため、HTTP 404も最終話判定に含めるよう修正。

## 調査したが対応を見送った事項

- **カクヨムの話ページ取得失敗**：自前Cloudflare Workersプロキシのヘッダーをブラウザらしい内容（User-Agent・Accept・Accept-Language・Referer）に改善する案を提示・試行したが、改善が見られなかった。ヘッダーよりもカクヨム側またはプロキシのIPアドレス単位でのレート制限/ブロックが濃厚と判断し、これ以上の対応は見送り現状維持とした。
- **Androidでのバックグラウンド再生**：Web Speech API使用時、Android ChromeはOS/ブラウザ側の制限によりバックグラウンド・画面ロック時に読み上げが停止しやすく、Web側からの回避策が乏しいためユーザー判断により対応不要とした。
