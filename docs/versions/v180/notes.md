# v180 リリースノート

## 変更点

### 章送りで「音声が中断されました」と出て停止する問題を修正した

Google TTSモード・iOS・画面消灯中に、履歴や目次から再生を始めると、その話の終わりの章送りで停止していた。リロード後や、一度停止してから ▶ を押し直した後は再発しなかった。

- 実機ログ：章送りで `stopGoogleAudioFull()` が `gAudioEl.src=''` にし（`G:error code4`）、次話の最初の段落を `play()` すると `G:playing`・`readyState 4` まで進むが `currentTime` が `0.00` のまま凍結し、`checkAudioProgress()` が断絶と判定していた
- 原因：再生していない間にiOSがこのページのバックグラウンド音声を拒否する状態になっており、▶ の時点では検出できない。鳴り続けている間（フォアグラウンド・段落送り）は再生できるが、空になった要素をバックグラウンドで鳴らし直す章送りで初めて表に出る
- 対策：Google TTSモードでは、画面の ▶ で再生を始めるたびに `_audioSessionLost` の有無に関わらず `rebuildAudioElements()` を実行する（`togglePlay()`）。修正後、実機で解消を確認した
- Web Speechモードは `gAudioEl` を使わないため、従来どおり中断検知後のみ作り直す
- `rebuildAudioElements()` で `play()` の連続失敗回数（`_playFailCount`）も0に戻す
- デバッグモードの `AudioContext` 状態ログ（`CTX`）を、作り直した新しいコンテキストにも付け直す。従来は最初のコンテキストにしか付かず、作り直し以降は記録されなかった

### 会話文の速度・ピッチ変更（SSML）機能を削除した

- 設定タブの「読み上げ演出」セクションと関連処理（`toSsml()` 等）を削除し、Google TTSには常にプレーンテキストを送る
- `yogatari_ssml_dialogue` は読み込まないが、既存端末のデータは削除しない。`docs/guide/storage.md` に廃止として記載した

### アイコンを作り直した

- `icon.svg`：グラデーション・マスクを廃止し、width/height指定付きの単色図形のみで描画する構成にした
- `icon-192.png` / `icon-512.png`：`icon.svg` と同じ三日月・星の絵柄に統一した。背景は角丸なしで全面に敷き、図柄を0.85倍に縮めてマスカブルアイコンの安全領域に収めた
- Safariのアイコンキャッシュ回避のためにURLへクエリを付与したが、取り消した（`index.html` の参照は v179 と同じ）

### README.md

- Google音声の再生中に「Load failed」が出る場合の対処（iPhoneの「Wi-Fiアシスト」をオフ）を追記した

## 決定事項

- 音声要素の作り直しはユーザー操作の内側でのみ行う。Media Sessionの再生ハンドラ、キューのチップ（`jumpQ()`）、章送りの自動再生は対象外とする。ユーザー操作の外で作った要素はiOSで `play()` を拒否されるため
- 詳細は `docs/guide/audio.md`「iOSバックグラウンド再生の実測挙動」に記載した
